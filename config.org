* Introduction

Emacs configuration that tries to use native features and when it doesn't use native features, it tells you why a package is used over native features. The configuration is targeted towards new users.

** UI

When you open Emacs, you see the following
- A menubar
- A toolbar
- A text editing area (A Window/Frame/Buffer)
- Modeline
- Echo area (Minibuffer)

** Menu

The menu is very useful for discovery and learning. It shows the keyboard shortcuts alongside menu label when a keyboard shortcut is available. The important keys are
- M - Alt
- C - Ctrl
- S - Shift

Emacs uses key chords so it is normal to find stuff like
- C-x C-f - Press Ctrl + x and then Ctrl + f
- M-x - Press Alt-x

The M-x shortcut is the most important for beginners, it allows searching from all the options functions at that moment

We will deep dive into learning Emacs once we have a proper setup

** Buffers

Emacs uses a concept of buffers, everything that it displays text is a buffer in Emacs. Think of them like Tabs that shows open file in other editors. Every opened file is a buffer in Emacs too. The difference comes with other things like File browser or Terminal, they are also buffers in Emacs. This is an advantage because all of your existing keyboard shortcuts work the same way in all the buffers.

** Modes

There are two types of Modes in Emacs
- Major mode
- Minor mode

To simplify things

- Major mode is a mode that is always active, a mode is applied to a buffer. If you open a JavaScript file =javascript-mode= will be active, it is a major-mode because only one type of mode can be active on a buffer. A major mode is more than a file type because when you open a Terminal or a File manager, a different major mode is active on those buffers to they behave as expected.
- Minor mode is a mode that adds some functionality and a lot of minor modes can be active at a time. For example, the tool-bar-mode or menu-bar-mode are minor modes. The spelling check or line number options are also minor modes.

** Buffer vs Minibuffer

In Emacs the =buffer= and the =minibuffer= are two major points of interaction and understanding both can help a lot when exploring the ecosystem.

The buffer is what shows the primary content whether it is a file, file manager, terminal, documentation, warning, errors, etc.

The minibuffer is used when user types =M-x= for running commands or =C-x C-f= for =find-file= which is used for opening an existing file or creating new file, opening info about the Emacs functions', variables', etc. Out of the box =minibuffer= only takes a single line but it be made multi-line, keep this in mind.

* Init

Add that to your =~/.config/emacs/init.el= and put this file at
=~/.config/emacs/config.org=. This will ensure the config.org is automatically
loaded as emacs config.

=org-babel-load-file= tangles the org file to =config.el= and loads that,
re-tangling only when the org file is the newer of the two.

#+begin_src emacs-lisp :tangle no

(org-babel-load-file
 (locate-user-emacs-file "config.org"))
#+end_src

** Load a dark theme

Before anything else, let's use the Emacs' =load-theme= function to set a theme

#+begin_src emacs-lisp :tangle no
(load-theme 'modus-vivendi-tinted)
#+end_src

You can also use *Menu* > *Options* > *Customize Emacs* > *Customize Themes*

If you want a light theme, you can try =modus-operandi-tinted=. You are free to try any other theme as well.

It is also possible to set third party themes as long as the package is installed.

When Emacs runs as a daemon, the config loads before any graphical frame exists, so =load-theme= applies against a frame-less display and the colors come out wrong in later =emacsclient= frames. The fix is to delay theme loading until the first client frame is created using =server-after-make-frame-hook=, and only load it directly when Emacs is started normally.

#+begin_src emacs-lisp :tangle yes
(use-package doric-themes
  :ensure t
  :config
  (defun my/load-theme (&rest _)
    "Load the theme, resetting any previously enabled themes first."
    (mapc #'disable-theme custom-enabled-themes)
    (load-theme 'doric-obsidian t))
  (if (daemonp)
      (add-hook 'server-after-make-frame-hook #'my/load-theme)
    (my/load-theme)))
#+end_src

** Enable line numbers

We can enable line numbers everywhere with

#+begin_src emacs-lisp :tangle no
(global-display-line-numbers-mode 1)
#+end_src

We can enable relative line numbers by setting the =display-line-numbers-mode= variable. =setq= and =setopt= (preferred) function is used for setting variables

#+begin_src emacs-lisp
(setopt display-line-numbers-type 'relative)
(setopt display-line-numbers-grow-only t)
(column-number-mode)
#+end_src

=global-display-line-numbers-mode= enables line numbers everywhere, including the terminal, file browser, help pages and everywhere else and that's not what we want so we will use hooks to enable the line numbers for only the certain modes. Hooks can be used to set or trigger something conditionally

#+begin_src emacs-lisp :tangle no
(add-hook 'prog-mode-hook 'display-line-numbers-mode)
(add-hook 'conf-mode-hook 'display-line-numbers-mode)
;; (add-hook 'text-mode-hook 'display-line-numbers-mode)
#+end_src

Here we have used ='prog-mode-hook=, all the programming languages related modes extend this mode so line numbers will automatically be enabled for all the programming languages. The ='conf-mode-hook= is for config files, it will also enable the line number for config files. We can use =text-mode-hook= for all the text files and it would automatically do that for config files as well as markdown and org files.

The other and simpler solution for enabling the line number in files is enabling when we open a file

#+begin_src emacs-lisp :tangle yes
(add-hook 'find-file-hook #'display-line-numbers-mode)
(add-hook 'lisp-interaction-mode-hook #'display-line-numbers-mode)
#+end_src

** Enable minibuffer history

Save minibuffer history so it is available when you restart Emacs, it will be used for ranking the auto suggestions when we will setup minibuffer enhancements.

=command-history= has to be excluded.  Savehist picks it up along with the real
minibuffer histories, but unlike them it records every interactive command
together with its arguments, and nothing ever truncates it -- it has no
=history-length= property, so =history-length= does not apply.  Left alone it
grows without bound; mine reached 27 MB and 9770 entries, which cost about half
a second of parsing on every single startup.

#+begin_src emacs-lisp

** Prettify symbols

Think of this like ligatures but on steroids.

=setq-default= is the wrong tool here, even though =prettify-symbols-alist= is
buffer-local.  Major modes that care about this feature -- =js-mode=,
=python-mode=, =emacs-lisp-mode= and friends -- assign the variable *buffer
locally in their own mode function*, which runs after the default value is
consulted and therefore throws the default away.  So a =setq-default= list
reaches only the modes that define no list of their own, which is to say
=text-mode=, =org-mode= and similar: exactly the prose modes where you least
want it.  That is backwards, and it is why plain English gets mangled -- "the
delta between the two is a map of pi values" renders as "the δ between the two
is a ↦ of π values".

The fix is to append to whatever list the major mode has already installed,
from a hook, so the mode's own entries survive alongside these.  Word-shaped
entries (=map=, =pi=, =sum=, =lambda=, the Greek letters) are gone: they cannot
tell a variable named =sum= from the English word, and the modes that genuinely
want =lambda= as λ already define it themselves.  Only operators remain.

#+begin_src emacs-lisp :tangle yes
(setopt prettify-symbols-unprettify-at-point t)

(defconst my/prettify-symbols-operators
  '(("==" . "≡")
    ("===" . "≣")
    ("!=" . "≠")
    ("!==" . "≢")
    (">=" . "≥")
    ("<=" . "≤")
    ("->" . "→")
    ("<-" . "←")
    ("<->" . "↔")
    ("<=>" . "⇔")
    ("->>" . "↠")
    ("<<-" . "↞")
    ("~>" . "↝")
    ("|>" . "▷")
    ("<|" . "◁")
    ("..." . "…")
    ("::" . "∷")
    (">>" . "»")
    ("<<" . "«"))
  "Operator substitutions for `prettify-symbols-mode'.
Operators only.  Word-shaped entries would fire on ordinary prose and on
identifiers that merely happen to spell a Greek letter.")

(defun my/prettify-symbols-setup ()
  "Add `my/prettify-symbols-operators' to the mode's own list and enable the mode.
Both steps happen here so the result does not depend on hook ordering."
  (setq-local prettify-symbols-alist
              (append my/prettify-symbols-operators prettify-symbols-alist))
  (prettify-symbols-mode 1))

(add-hook 'prog-mode-hook #'my/prettify-symbols-setup)
#+end_src

Note this is now =prog-mode= only.  =text-mode= was dropped deliberately: with
the word entries gone there is little left that helps prose, and =::= would
collide with org's description-list syntax (=- term :: definition=).  Add
=(add-hook 'text-mode-hook #'my/prettify-symbols-setup)= to put it back.

** Backup files

Emacs creates three kinds of extra files next to the file you are editing:
- =file~= (backups)
- =#file#= (auto-saves)
- =.#file= (lock files)

This is annoying because it clutters directories and these files show up in git operations. Instead of disabling them, let's relocate all three into a single =.backups= directory under =user-emacs-directory=.

#+begin_src emacs-lisp :tangle yes
(let ((backup-dir (concat user-emacs-directory ".backups/")))
  ;; Emacs won't create this for us; without it backups silently fall back
  ;; to sitting next to the original file.
  (make-directory backup-dir t)
  ;; file~ backups
  (setopt backup-directory-alist `(("." . ,backup-dir)))
  ;; #file# auto-saves
  (setopt auto-save-file-name-transforms `((".*" ,backup-dir t)))
  ;; .#file lock files (Emacs 28+)
  (setopt lock-file-name-transforms `((".*" ,backup-dir t))))
#+end_src

** Auto Revert

It means when the file changes on the disk, update the open buffer

Two options are worth setting alongside it.

=auto-revert-avoid-polling= switches from stat-ing every file on a timer to
using the OS file-notification support, so idle Emacs stops doing periodic work
proportional to how many buffers are open.  Emacs still falls back to polling
for files on filesystems that cannot notify, such as most remote TRAMP paths.

=global-auto-revert-non-file-buffers= extends the same treatment to buffers
that are not visiting a file, which in practice means Dired and Dirvish
refreshing when a directory's contents change underneath them.

#+begin_src emacs-lisp :tangle yes
(setopt auto-revert-avoid-polling t)
(setopt global-auto-revert-non-file-buffers t)
(global-auto-revert-mode 1)
#+end_src

Recursively scan org files for org agenda

Note =\\'= rather than =$= as the anchor.  In a regexp =$= matches at a
newline as well as at the end of the string, so on a filename it is the
wrong anchor even though it usually behaves; =\\'= matches only the true end.

This runs on every =org-agenda= and =org-refile= invocation, and =org-directory=
is also =org-roam-directory=, so every roam note gets scanned too.  If that ever
becomes slow, this is the thing to make lazier.

#+begin_src emacs-lisp :tangle yes
(defun my/org-refresh-agenda-files (&rest _)
  "Rescan `org-directory' so new files are included in the agenda."
  (setopt org-agenda-files (directory-files-recursively org-directory "\\.org\\'")))
#+end_src

Run this function before org agenda is loaded

#+begin_src emacs-lisp :tangle yes
(advice-add 'org-agenda
  :before
  #'my/org-refresh-agenda-files)
#+end_src

** Last Updated Hook

I like a keeping =#+LAST_UPDATED:= heading in my org files, I add a custom function and a save hook to update it.

#+begin_src emacs-lisp :tangle yes
(defun my/org-update-last-updated ()
  (when (eq major-mode 'org-mode)
    (save-excursion
      (goto-char (point-min))
      (when (re-search-forward "^#\\+LAST_UPDATED:" nil t)
        (delete-region (point) (line-end-position))
        (insert " " (format-time-string "[%Y-%m-%d %a %H:%M]"))))))
#+end_src

Add a before save hook to update the =LAST_UPDATED= field

#+begin_src emacs-lisp :tangle yes
(add-hook 'before-save-hook #'my/org-update-last-updated)
#+end_src

** Disable src indentation

A named function rather than a lambda.  =add-hook= dedupes by comparing the
function it is given against what is already on the hook, and a lambda gives it
nothing stable to compare -- so re-evaluating the config (=my/reload-config=
does exactly that) risks stacking up copies.  A named symbol also means the
hook can be inspected with =C-h v org-mode-hook= and removed again.

#+begin_src emacs-lisp :tangle yes
(defun my/org-disable-electric-indent ()
  "Turn off `electric-indent-mode' locally, so src blocks are left alone."
  (electric-indent-local-mode -1))

(add-hook 'org-mode-hook #'my/org-disable-electric-indent)
#+end_src

** Org Roam

=org-roam-setup= is an obsolete alias -- org-roam 2.0 renamed it, and calling it
prints a byte-compiler warning.  =org-roam-db-autosync-mode= is the current
name, and being a real minor mode it also takes an explicit argument.

The directory is the same tree as =org-directory=, so it is derived from that
rather than written out a second time; the two drifting apart would put the
roam database somewhere the agenda never looks.

#+begin_src emacs-lisp :tangle yes
(use-package org-roam
  :ensure t

* Packages

This is a list of third party packages as well as first party packages that are very useful for enhancing the UX.

** Introduction

Emacs has packages, they are like plugins. Emacs is an elisp interpreter which means it runs =elisp= code. Most of Emacs is written in =elisp=. In order to customize Emacs, the user only needs to change variables in emacs which we have done a few times with =setq= or by calling functions, we have called many functions with 1 or -1 parameter as well as t parameter which stands for true (Everything non nil is true). In order to change behavior or Emacs, we can add our own functions or extend the built-in functions. Most packages just do that. Emacs is insanely extensible and that's why it is possible to emulate vim in Emacs with evil mode but the extensibility doesn't end there. The possibilities are literally infinite because Emacs is a programmable editor and each user makes changes that suites their own. Now let's look at some of the packages that enhances experience by extending the feature in Emacs or by providing new features.

The basic setup is sufficient for most packages. If extra setup is needed then it is explicitly stated. You can always go to the project documentation to learn more about available options.

=use-package= function is used for using the built-in package manager.

** Completion

The completion packages fall into three categories in Emacs

- In buffer completion
- Minibuffer completion
- Both

*** Minibuffer

**** Vertico

Vertico is a third party package, it is used for enabling vertical list in minibuffer. The name stands for =VERTICal Interactive COmpletion=.

We can enable the vertical minibuffer with the built-in =fido-vertical-mode=.

#+begin_src emacs-lisp :tangle no

#+end_src

So why add *Vertico* if =fido-vertical-mode= already does what we want? Because the built-in =fido-vertical-mode= doesn't work with third party completion styles, we will see that when we setup *Orderless*. Marginalia (set up next) works fine with either.

This basic setup is sufficient.

#+begin_src emacs-lisp

  :ensure t
  :init
  (vertico-mode 1))
#+end_src

- =C-h f= : Shows function description

**** Orderless

Orderless is a completion style package, it adds an =orderless= completion style. Emacs uses completion styles to narrow down a list against a query.

=orderless= completion style allows typing =M-x buffer list= for =M-x list-buffers=, you can even type =buff lis= and still matches. As the name suggest, you can type the part of the input in any order and they will work.

Custom functions to encrypt and decrypt age files

#+begin_src emacs-lisp :tangle yes
  (defun my/age-decrypt-current-file ()
    "Decryption current age encrypted file"
    (interactive)
    (let* ((file (buffer-file-name))
  	 (decrypted (and file (string-suffix-p ".age" file t)
  			 (file-name-sans-extension file))))
      (unless file (user-error "Buffer is not visiting a file"))
      (unless decrypted (user-error "Current file is not age encrypted"))
      (unless (executable-find "age")
        (user-error "age not installed"))
      (when (and (file-exists-p decrypted)
  	       (not (yes-or-no-p (format "%s exists; overwriting? " decrypted))))
        (user-error "Aborted"))
      (when (buffer-modified-p)
        (user-error "Please save changes before decrypting"))

      ;; Call age program to decrypt it
      (let ((status (call-process "age" nil nil nil
  				"--decrypt"
  				"--identity" (expand-file-name "~/.config/age/primary")
  				"--identity" (expand-file-name "~/.config/age/yubikey_primary")
  				"--identity" (expand-file-name "~/.config/age/yubikey_backup")
  				"--output" decrypted
  				file)))
        (if (zerop status)
  	  (progn
  	    (kill-buffer (current-buffer))
  	    (delete-file file)
  	    (find-file decrypted)
  	    (message "Decrypted to %s" decrypted))
  	(user-error "Age decryption failed (exit %s)" status)))))

  (defun my/age-encrypt-current-file ()
    "Encrypt current file with age"
    (interactive)
    (let* ((file (buffer-file-name))
  	 (encrypted (concat file ".age")))
      (unless file (user-error "Buffer is not visiting a file"))
      (when (string-suffix-p ".age" file t)
        (user-error "Current file is already age encrypted"))
      (unless (executable-find "age")
        (user-error "age not installed"))
      (when (and (file-exists-p encrypted)
  	       (not (yes-or-no-p (format "%s exists; overwriting? " encrypted))))
        (user-error "Aborted"))
      (when (buffer-modified-p)
        (user-error "Please save changes before encrypting"))

      ;; Call age program to encrypt it
      (let ((status (call-process "age" nil nil nil
  				"--encrypt"
  				"--recipients-file" (expand-file-name "~/.config/age/primary.pub")
  				"--recipients-file" (expand-file-name "~/.config/age/yubikey_primary.pub")
  				"--recipients-file" (expand-file-name "~/.config/age/yubikey_backup.pub")
  				"--output" encrypted
  				file)))
        (if (zerop status)
  	  (progn
  	    (kill-buffer (current-buffer))
  	    (delete-file file)
  	    (find-file encrypted)
  	    (message "Encrypted to %s" encrypted))
  	(user-error "Age encryption failed (exit %s)" status)))))

** Pandoc File Type Conversion

Pandoc is a package that allows conversion between markdown, org, and many other file formats.

*** Markdown to Org

Uses pandoc to convert markdown to org

#+begin_src emacs-lisp :tangle yes
  (defun my/md-to-org()
    "Convert current markdown file to org"
    (interactive)
    (let ((file (buffer-file-name)))
      (unless (and file (string-match-p "\\.md\\'" file))
        (user-error "Current buffer is not a markdown file"))
      (unless (executable-find "pandoc")
        (user-error "Pandoc is not installed"))
      (when (buffer-modified-p)
        (user-error "Please save the changes"))

      ;; The file is ready for conversion, no blockers
      (let ((org-file (concat (file-name-sans-extension file) ".org")))
        (when (and (file-exists-p org-file)
  		 (not (yes-or-no-p (format "%s exists; overwrite? " org-file))))
          (user-error "Aborted"))
        (let ((status (call-process "pandoc" nil nil nil
  				  "--from" "markdown"
  				  "--to" "org"
  				  "--output" org-file
  				  file)))
          (unless (zerop status)
  	  (user-error "Pandoc conversion failed (status %s)" status))
          (kill-buffer (current-buffer))
          (find-file org-file)
          (message "Converted %s -> %s" (file-name-nondirectory file) (file-name-nondirectory org-file))))))
#+end_src

* Tips

** Autocomplete

You can use =M-/= to auto-complete a word that already exists in open buffers. It is really helpful when typing long words, if the correct word is not matched on the first try, press it again and again till you get it right

** Mode Specific Commands

You can use =M-S-x= to search for options that only applies to current major mode, this is really helpful for learning what options are available for current buffer instead of searching all available options.

** Efficient ibuffer

=ibuffer= is a command that shows a list of all buffers, it is interactive so you can mark the buffers with =d= and delete the marked buffers with =x=, really useful for closing a bunch of buffers at once. If you have menu-bar enabled, you can see all the options in the *Menu* > *Operate*

** Editing files with sudo

To edit files with sudo using Emacs, append ~/sudo::~ before the file path and the file will be opened as sudo.

*** Sudo with tramp

=sudo= can be used with tramp to edit files on the remote server as root, I am going to use the server =test-server= as an example here. Enter the following in the find file

#+begin_example
/ssh:user@test-server|sudo::/etc/fstab
#+end_example

** Preview unsaved changes

Use =diff-buffer-with-file= to see what's new in the buffer that's not on the disk. This is specially useful when you run a command by accident and not sure what's changed

** Menu and Context Menu

Even if Menubar is disabled, you can open it with =F10= for global menu and =S-F10= (Shift + F10) for context menu. I used it randomly because it helps in discoving new things

* Load the custom file

This is deliberately the last thing the config does.

=custom.el= is written by the Customize UI -- *Menu* > *Options* > *Customize
Emacs* > *Apply and Save*.  Loading it early, which is the obvious place and
where it used to live, means every =setopt= in the rest of this file runs
afterwards and silently overwrites whatever you saved through the UI.  You get
no error and no warning; the setting simply does not stick, and the Customize
buffer keeps cheerfully reporting the value you chose.

That bit me once already: =erc-autojoin-channels-alist= was set in both places
with different channel lists, and because =custom.el= loaded first, the copy in
this file won without either one admitting it.  Loading last inverts the rule
into something predictable -- *whatever you set through the UI wins* -- which is
the behaviour you want from a UI whose entire purpose is overriding things.

The tradeoff is that a stale entry in =custom.el= can now quietly defeat an edit
made here.  If a setting refuses to take effect, grep =custom.el= first.

The =t t= arguments mean: do not error if the file is missing, and do not print
a load message.

#+begin_src emacs-lisp :tangle yes
(load custom-file t t)
#+end_src
